TM032 copies bounded color tables, direct target channels/visibility, visual
material scalar diagnostics, view shape/dimension links and classic DimTol values
and shape associations. Typed labels must belong to the exact existing projection
context; native labels/tools/arrays never escape. Read-only snapshots do not create
missing tools. A caller-open command is required for mutation; a nested native
transaction aborts each failed operation. All batch targets validate before writes.

Material creation initializes untextured PBR scalars and assigns one material to
explicit shape/occurrence targets. Unicode names use explicit UTF8 conversion.
A private imported document subclass calls SDK BeforeClose before member destruction, clearing naming undo/redo deltas while Data is alive. Generated bare documents do not prove that protocol; saved-camera creation accepts only the application-backed domain or this private close-safe owner. A naming-backed generic SDK owner destruction crash was reproduced and captured with a native stack.
A generated exact XML color adapter preserves bounded RGBA bits beside the SDK nearest-name payload. Only OcctSharp-aware XML drivers promise exact custom RGBA; legacy readers retain nearest named colors. Retrieval uses the actual LDOM string attribute because getAttributeNode can report absence for this parsed node. A nonnumeric version prefix preserves transparent black. Malformed extensions fail closed; absent extensions use the SDK legacy driver.
Nested removal explicitly backs up view subtree attributes before the SDK ForgetAllAttributes path, retaining outer abort and undo/redo deltas.
Views initialize every camera scalar before SetObject; no default uninitialized
XCAFView_Object numeric field is read. Views associate explicit shape/DimTol labels.
Classic DimTol is a copied native kind/value profile, not general semantic GD&T.
It permits one exact shape association: pinned SetDimTol reparents its tree node,
so looping over multiple targets would silently replace earlier associations.
Multi-shape semantic dimension profiles, arbitrary clipping/notes/annotation
channels, textures, physical material conversion and deletion cascades remain
deferred. Empty/nullable native arrays remain distinct in snapshots.

TM033 uses call-private initialized STEPCAF readers/writers. Explicit mode setters
are verified with matching getters. Reader modes include colors, names, layers,
properties, metadata/product metadata, SHUO, GD&T, materials and views. Writer
modes include colors, names, layers, properties, metadata, SHUO, GD&T, physical/
visual materials and duplicate cleanup; the SDK has no separate writer ViewMode.
Export requires a committed document and ordinary single-file AsIs transfer.
Import allocates a fresh owning generated document, initializes XCAF/undo state,
and publishes only after complete transfer and copied free-root diagnostics.
Its owning SDK document retains the private BeforeClose destructor protocol.
Reader/writer/work-session/maps/streams/external-file objects never escape.
Paths and root projections are bounded; a source-file SHA256 is copied and checked
again after import. Root entries identify this exact document and do not establish
cross-file topology identity. File output is not a transactional filesystem API.

Existing manual presentation metadata and AS/AT workflows are reused, not
overwritten. Tests cover distinct repeated occurrence assignments, command
undo/redo, BinXCAF and XmlXCAF reopen, actual assembly STEPCAF transfer/readback,
file identity, context/parent disposal, errors and independent copied snapshots.
XCAF persistence checks material/view/DimTol associations. STEP assertions prove
the declared assembly/name/color/root path; they do not imply universal semantic
GD&T or PBR interoperability in third-party CAD software.
