## Intended outcome and order

1. Prove independent shape/entity element lifetimes and typed sequence/list ownership.
   Distinguish deep geometry copies, shared immutable topology, transient entities and
   borrowed history references. Preserve location/orientation and dynamic type.
2. Close collection input/output across Boolean builder/splitter/defeaturing, sewing
   and same-domain unification. Carry arguments, tools, modified/generated/history
   and resulting shape sets together. Validate empty sets, duplicates, shared topology,
   disposal, partial failures and wrong tokens.
3. Connect the resulting independent shape sets to existing repair diagnostics,
   conservative history resolution and exact selection. Multiple paths, split/merge
   and unproved associations remain explicit unresolved results.
4. Close exchange entities/transfer results through reader, transfer process, graph
   and entity iteration, retaining parent/epoch restrictions until independently owned
   snapshots are proved. Verify returned indices and runtime dynamic types against
   concrete STEP/IGES files.
5. Run one shared public-only workflow in Runtime and both consumers: multiple input
   shapes -> Boolean/history -> independent result set -> inspection/repair -> STEP
   or IGES -> transferred entity/shape inspection. Include error cases and results
   surviving source algorithm/document disposal where ownership permits.

## Admission and delivery

Before each family is emitted, record every exact ID/signature, native symbol,
constructor state, capacity/iteration order, retention, failure publication and
complete consumer use. Reuse AH typed registry/publication rules only after proving
the different element semantics. Shape identity and topology history cannot be
inferred from geometric proximity. Arbitrary templates and borrowed pointers remain
closed. Numeric workspaces deferred by AH enter a later explicit geometry contract
audit when a caller workflow requires them.

Treat all candidates as PLANNED_CANDIDATES_NOT_ADMITTED. Supporting already-emitted
and Manual prerequisites are separate accounting. Preserve prior output/API/exports,
refresh exact inventory, and complete the same full local engineering delivery gates
before enlarging the migration scope. Hosted CI, signing and public release stay
separate from local validation.
