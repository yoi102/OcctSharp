# ADR-0140: public consumer copy/history and exact exchange support

Accepted 2026-10-12 within the user-authorized Cadoryx public SDK migration.

Existing generated public adapters and the single native bridge remain owners
of their contracts. Admit explicit OCCT 8.0.1 header-pinned support profiles for
defeature history, exact STEP offset graph completion and periodic distance.
Extend the existing exact-consumer support contract with input/history values
and initial viewer display. Embedded template hashes and deterministic manifest
outputs own the new support code; these workflows add no raw StableId credit.

Input-copy reports use independent bounded values, per-argument source/copy
native membership, and explicitly separate source and target domains. History
reports retain actual native source identity and check targets against the
actual final result. TopExp membership does not prove occurrence paths,
serialized origin, composed references or unique cross-argument binding.
Ambiguous/missing membership is reported rather than inferred.

Defeature reuses RepairSnapshot and LocalFeatureResult ownership and serial
private execution. STEP read/write scopes operate on private geometry and real
representation contexts; original graph/units/root ordering survive. Periodic
distance preserves trimmed-face classifications and bounded geometry refinement.
No new raw pointer, borrowed result or cross-DLL owner category is introduced.

Initial display must apply mode before native Display, retaining viewer thread,
source-owner/disposed guards and isolation tracking. New managed calls require
public ABI 1.118; older public ABI 1.117 numerically exceeds private 1.86 but
does not contain the new exports. The public bridge version becomes 0.133.0.

Pack pins every intra-family project dependency to the exact validated version.
The 13 managed packages and single native package cannot silently resolve a mixed
preview family. This changes pack metadata only; runtime/restore/build ownership
is unchanged. Fresh nuget.org consumers must verify all resolved family versions.

Private validation is provenance only. Fresh public full delivery, packaging
and remote consumers remain required. The external stock-reader strict STEP
failure is retained independently of public support migration/publication.
